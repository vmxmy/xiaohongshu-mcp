# 登录安全认证二维码识别设计

## 背景与目标
当前登录流程在“安全认证/扫码验证”阶段会展示第二张二维码，但文本提示与二维码元素位于 iframe 中，导致仅扫描主文档时无法识别该阶段，返回的仍是登录二维码。目标是在不新增工具的前提下，准确识别安全认证阶段并返回对应二维码，同时保持现有登录阶段行为不变。

## 范围与非目标
- 范围：仅改进二维码识别与安全提示检测逻辑。
- 非目标：不修改登录工具入口、不改变 cookie 保存策略、不引入新依赖或新工具。

## 设计要点
1. 安全提示检测：在主文档检测失败时，递归扫描所有 iframe 的 `body` 文本，匹配“安全认证/扫码验证/二维码失效”等提示。
2. 二维码定位策略：
   - 若检测到安全提示：优先在 iframe 树内查找二维码元素，找不到再回退主文档。
   - 否则：保持原有主文档优先策略。
3. 错误处理：若全局找不到二维码，返回明确错误，便于日志定位。

## 数据流与接口
- `QRCode(ctx)`：先判断阶段（login/security），再按阶段策略定位二维码元素并截图。
- `frameHasSecurityHint` 与 `findQRCodeElementInFrame` 作为递归工具函数复用，保持单一职责。

## 测试策略
- 新增失败用例：主文档仍存在登录二维码，但 iframe 出现安全提示与安全二维码时，应返回安全阶段与 iframe 二维码。
- 保留现有测试，确保登录阶段行为不回归。

## 工程原则落实
- KISS：仅调整阶段判定与搜索优先级。
- YAGNI：不引入新工具或新参数。
- SOLID：阶段判定与元素定位解耦。
- DRY：递归逻辑复用。
